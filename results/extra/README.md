# 参数变化附加实验

本目录是选做分析，**不改变** `results/` 下的默认基线 8 组结果。所有数字由 `param_sweep.py` 用本仓库的实现现场运行得到，重复运行结果一致（无随机性，`light_random` 不参与本扫描）。

运行方式（在仓库根目录）：

```powershell
.\.venv\Scripts\python.exe results/extra/param_sweep.py
```

## 1 条件

除被扫描的参数外，其余均为默认配置：4 用户、256 tick、128 bit/tick、tick_ms=1、seed=2026。

| 实验 | 扫描参数 | 取值范围 | 参与场景 |
|---|---|---|---|
| 包头敏感性 | `header_bits` | 0, 16, 32, 64 | continuous、staggered_burst |
| 缓存敏感性 | `buffer_payload_bits` | 512, 1024, 2048, 4096, 8192 | continuous、staggered_burst |

电路模型不使用包头，因此 `header_bits` 对电路结果没有影响（表中数值不变），它在本实验中的作用是**对照组**：用来确认分组结果的变化确实来自包头，而不是其他因素。

## 2 包头敏感性（continuous）

| header_bits | 模型 | 有效载荷利用率 | 线路忙碌率 | 丢失率 | 积压 (bit) |
|---:|---|---:|---:|---:|---:|
| 0 | 电路 | 100.0% | 100.0% | 0 | 0 |
| 0 | 分组 | 100.0% | 100.0% | 0 | 0 |
| 16 | 分组 | 88.7% | 100.0% | 0 | 3712 |
| 32 | 分组 | 79.7% | 100.0% | 9.0% | 3712 |
| 64 | 分组 | 66.4% | 100.0% | 21.9% | 3840 |

**观察**：包头为 0 时分组与电路在连续满载下完全等价（都是 100%），说明两者的差异确实由包头产生。包头从 16 bit 增至 64 bit 时，分组在同样 100% 线路忙碌率下可交付的 payload 从 88.7% 降到 66.4%，丢失率从 0 升到 21.9%——对每条 128 bit 的记录而言，16 bit 包头就是 12.5% 的额外线路开销，头越长，同样窗口内能送出的记录越少。

## 3 包头敏感性（staggered_burst）

| header_bits | 模型 | 有效载荷利用率 | 线路忙碌率 | 丢失率 |
|---:|---|---:|---:|---:|
| 0 | 分组 | 75.0% | 75.0% | 0 |
| 16 | 分组 | 75.0% | 87.5% | 0 |
| 32 | 分组 | 75.0% | 100.0% | 0 |
| 64 | 分组 | 59.8% | 100.0% | 3.9% |

**观察**：只要 `96 + header ≤ 128`（header ≤ 32），分组都能一 tick 处理一条，有效载荷利用率恒为 75%，只是线路越来越忙；一旦 header 超过 32 bit（如 64），一条记录需要两个时隙，开始出现积压和丢弃，有效载荷利用率跌到 59.8%。这给出一个可解释的设计边界：**包头预算必须小于等于“时隙 − 典型分组长度”**。

## 4 缓存敏感性（continuous/分组）

| 缓存 (bit) | 有效载荷利用率 | 丢失率 | 平均时延 (ms) | 积压 (bit) |
|---:|---:|---:|---:|---:|
| 512 | 79.7% | 19.9% | 3.5 | 128 |
| 1024 | 79.7% | 18.4% | 8.2 | 640 |
| 2048 | 79.7% | 15.2% | 16.1 | 1664 |
| 4096 | 79.7% | 9.0% | 26.1 | 3712 |
| 8192 | 79.7% | 0 | 28.5 | 6656 |

**观察**：缓存不改变“线路已满、有效载荷利用率锁死在 79.7%”这一事实，但它决定了过载部分以**丢弃**还是**积压**的形式存在。缓存越小，越早丢弃、排队越短、平均时延越低（512 bit 时只有 3.5 ms），但丢失率高达 19.9%；缓存越大，越倾向于排队，丢失率降为 0，代价是 6656 bit 积压和 28.5 ms 时延。**这正是“平均时延低不等于系统好”的反例：低时延可以靠提前丢包买到。**

## 5 缓存敏感性（staggered_burst/电路）

| 缓存 (bit) | 有效载荷利用率 | 丢失率 | 平均时延 (ms) | 积压 (bit) |
|---:|---:|---:|---:|---:|
| 512 | 28.7% | 60.2% | 12.4 | 384 |
| 1024 | 33.1% | 52.3% | 20.7 | 864 |
| 2048 | 42.8% | 35.2% | 32.2 | 1920 |
| 4096 | 49.2% | 18.4% | 45.1 | 3936 |
| 8192 | 56.0% | 0 | 56.4 | 6240 |

**观察**：电路模型在错峰突发下已经严重过载（热点用户只有 1/4 时隙），扩大缓存只能把丢弃换成更长的排队：缓存 8192 bit 时虽然零丢失，但仍有 6240 bit 积压，平均时延 56.4 ms。**增加缓存不产生带宽，只改变排队与丢弃的比例。**

## 6 结论与适用条件

1. 包头是分组交换的固定成本，其影响在“记录长度接近时隙”时被放大；本实验默认 32 bit 头对 96/128 bit 记录是 25%～33% 的开销。
2. 缓存容量是“丢弃—积压—时延”的调节旋钮，不改变链路的长期承载能力。
3. 上述结论只适用于本实验的单链路、已建立连接、有限窗口模型；改变包头或缓存后，默认基线的 8 组比较仍以 `results/comparison.csv` 为准，不能混用两套参数。
